TanStack Query handles:

API loading states
Caching
Error states
Refetching
Pagination
Mutations
Cache invalidation

The app will connect to the NestJS API under /v1, using bearer authentication and cursor pagination as defined in the API specification.

State management
TanStack Query for backend/server data
Zustand for small global client state
React state for local component state

Architecture style

Use a feature-based architecture:

src/
├── app/             # Expo Router screens
├── features/        # Feature logic and components
├── components/      # Shared generic components
├── api/             # Axios and TanStack Query setup
├── auth/            # Session and token handling
├── services/        # Location, notifications, WebSocket
├── stores/          # Small Zustand stores
├── theme/           # Design tokens
├── localization/    # French and Arabic
├── types/
└── utils/

Inside features:

features/
├── auth/
├── services/
├── profile/
├── carpool/
│   ├── places/
│   ├── search/
│   ├── trips/
│   ├── bookings/
│   ├── publishing/
│   ├── vehicles/
│   ├── tracking/
│   ├── conversations/
│   └── reviews/
├── payments/
├── wallet/
├── notifications/
└── support/

Only carpool is active now. Taxi, food, and grocery should only appear in the service catalogue as coming_soon, matching the backend service configuration.
